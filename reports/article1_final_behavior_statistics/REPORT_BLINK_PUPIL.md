# Article 1 — blink and pupil

**Status: `exploratory_pilot`.**
**Interpretation: ocular measurement, not clinical, not a drowsiness score.**

Generated by `scripts/extract_article1_eye_state.py`. Data:
`output/article1/final_behavior_statistics/<recording_id>/eye_state_samples.parquet`,
`blink_events.parquet`, `blink_rate_windows.parquet`, `pupil_samples.parquet`,
`eye_state_summary.json`. Figure `figures/10_blink_pupil_comparison.png`.

Nothing in this report is a medical measurement. Eye-closure fraction is **not**
called drowsiness, PERCLOS or fitness to drive; pupil diameter is **not**
interpreted as cognitive load, arousal or impairment. Those are not caveats added
at the end — they are the reason the metrics are named the way they are.

## Where the data came from, and why it needed new code

The eye-gaze record in these recordings declares, in its own embedded VRS
`DataLayout`:

```
left_eye/pupil_diameter_valid   Bool    offset 55
left_eye/pupil_diameter_meter   float   offset 56
left_eye/blink_valid            Bool    offset 60
left_eye/blink                  Bool    offset 61
   ... and the mirrored right-eye block at offsets 101, 102, 106, 107
```

`projectaria_tools` 2.1.2 binds this record into `mps.EyeGaze` /
`mps.EyeGazeVergence`, which expose the two blink flags and their validity flags —
but **not** the pupil diameter. The data is in the file; only the binding is
missing.

`behavior/eye_state.py` therefore decodes the record payload directly. Three
things keep that honest:

* **the layout is read from the file.** Field names, types and byte offsets come
  from the descriptor this recording carries, so a device or firmware writing a
  different layout is decoded correctly or refused — never decoded wrongly;
* **the stream is identified by content**, not by a hardcoded id: the only record
  type accepted is the one whose decoded tracker timestamp reproduces its own VRS
  record-header timestamp;
* **every decode is verified against the official binding, sample by sample.**

| verification | car | motorcycle |
|---|---:|---:|
| samples decoded | 11 283 | 30 138 |
| samples in `projectaria_tools` | 11 283 | 30 138 |
| max timestamp error | **0 ns** | **0 ns** |
| max convergence-distance error | **0.0 m** | **0.0 m** |
| flag mismatches over 8 boolean fields | **0** | **0** |

The verified fields sit at buffer offsets 0, 29, 60, 61, 75, 106, 107, 121, 135
and 158 — the two pupil-diameter fields are at 56 and 102, bracketed on both
sides. If all ten agree on every sample, the buffer cannot be misaligned and the
pupil bytes are read where the file says they are. The extraction script refuses
to write a table that fails this check.

Sampling: 30.000 Hz measured from the stream's own timestamps in both
recordings, median interval 33.333 ms, maximum 33.334 ms, strictly increasing.
**Nothing is interpolated, resampled or gap-filled**, and an invalid pupil
reading keeps its `False` validity flag and a NaN diameter rather than a
neighbour's value.

## The blink flag's polarity is measured, not assumed

The field named `blink` is `True` for 92.7% (car) and 88.9% (motorcycle) of
samples. Read literally that is a rider with their eyes shut for nine tenths of a
drive, which is not a thing that happened.

`determine_blink_polarity` decides from the run-length distribution instead. A
blink is short and rare; an open eye is long and common, so the closed state is
the polarity that is **both** rarer and shorter-running:

| raw flag value | car sample share | car median run | motorcycle sample share | motorcycle median run |
|---|---:|---:|---:|---:|
| `True` | 92.7% | 1.367 s | 88.9% | 0.767 s |
| `False` | **7.3%** | **0.100 s** | **11.1%** | **0.067 s** |

A 100 ms run occurring 30 times a minute is a blink. A 1.4 s run occupying 93% of
the recording is an open eye. The polarity is decided as `blink == False` means
**eye closed** in both recordings, the evidence is stored with every summary, and
if the two polarities were not clearly separated the module would return
`undetermined` and refuse to emit events rather than pick one.

**The raw values are stored unchanged.** `left_blink`, `right_blink`,
`left_blink_valid` and `right_blink_valid` are in the sample table exactly as the
device wrote them; the polarity is applied only when deriving closure.

An independent check confirms it. Gaze cannot be estimated through a closed
eyelid, so if the closed state has been identified correctly, gaze invalidation
should coincide with it:

| | car | motorcycle |
|---|---:|---:|
| gaze invalid overall | 6.8% | 10.3% |
| gaze invalid **during** closure | 85.9% | 83.2% |
| gaze invalid while open | 0.24% | 0.58% |
| **invalid-gaze samples explained by closure** | **96.7%** | **95.1%** |

That is not a metric of interest in itself — it is instrumentation behaving as it
must — but 96% and 95% agreement between two independently derived signals is
what makes the polarity decision safe to build on.

## Blink events

An event is a maximal run of consecutive **real** samples that are not in the open
state. A sampling gap larger than 75 ms ends the run rather than being bridged,
because the state during a gap was not recorded and this analysis does not invent
it. Events are classified into the five permitted categories:

| category | car | motorcycle |
|---|---:|---:|
| `bilateral_blink` | 159 | 752 |
| `left_only` | 31 | 102 |
| `right_only` | 5 | 42 |
| `uncertain` | 2 | 8 |
| `invalid_tracking_gap` | **0** | **0** |
| **identified blinks** | **195** | **896** |

`uncertain` catches two things and records which: a run where both eyes close but
never on the same sample, and a closure longer than 1 s, which is a prolonged
closure and does not belong in a blink-rate denominator. `invalid_tracking_gap`
would catch runs where both blink flags are marked invalid; both recordings
report 100% blink validity, so it is empty here — which is a result, not an
omission.

A monocular event is as likely to be a per-eye tracking failure as a genuine
one-eyed blink. The left/right counts are reported and **not** interpreted.

## Rates, durations and intervals

| metric | car | motorcycle |
|---|---:|---:|
| blinks/min, whole recording | **31.1** | **53.5** |
| blinks/min including `uncertain` | 31.4 | 54.0 |
| 60 s windows stepping 10 s | 32 windows | 95 windows |
| window rate range | 21 – 45 /min | 27 – 83 /min |
| mean blink duration | 0.146 s | 0.131 s |
| median blink duration | **0.133 s** | **0.133 s** |
| p95 blink duration | 0.267 s | 0.233 s |
| median inter-blink interval | 1.53 s | 0.90 s |
| p95 inter-blink interval | 4.70 s | 2.70 s |
| bilateral share | 81.5% | 83.9% |
| **eye-closure fraction, both eyes** | **6.2%** | **9.3%** |

Windows are 60 s stepping 10 s, defined in seconds and applied to the stream's own
timestamps; a window is only reported when it fits entirely inside the recording,
so no rate is ever computed over less time than it claims.

Three things constrain how far these numbers can be read:

* **duration is quantised to 33 ms.** At 30 Hz a 133 ms median blink is four
  samples. The median is stable, but the distribution's shape below ~100 ms is
  set by the sampling rate as much as by the eyelid;
* **this is the on-device detector's output, not a validated blink count.** It has
  not been checked against EOG or high-speed video here. The absolute rate should
  be read as a device metric;
* **the between-vehicle contrast is the interpretable part** — same device, same
  wearer, same detector, same firmware — and it is large: +18.0 blinks/min on the
  shared route (95% CI [10.2, 30.3], Cliff's δ = +0.54, p_FDR = 0.015), reproduced
  independently on 30 s time blocks over the whole recording (+23.0/min,
  δ = +0.87, p_FDR = 0.008).

What that difference *means* this pilot cannot say. A higher blink rate on a
motorcycle is consistent with airflow and ocular drying, with a visor, with light
level, with two sessions weeks apart, and with the rider simply being a different
kind of busy. All of those are confounded with the vehicle here.

## Eye-closure fraction

6.2% (car) and 9.3% (motorcycle) of valid samples have both eyes closed. In the
paired bin comparison the difference is +0.017 with a 95% CI of [0.008, 0.044]
and does **not** survive FDR (p_FDR = 0.142).

This is the fraction of time the eyelids were down, which for a blink rate of
31–54/min at ~133 ms each is arithmetic rather than news. **It is not a drowsiness
measurement.** PERCLOS-style measures use a specific closure threshold, a specific
window, and validation against a reference; none of those is present here, and
nothing downstream may relabel this figure as drowsiness, fatigue, microsleep or
fitness to drive.

## Pupil diameter

| | car left | car right | motorcycle left | motorcycle right |
|---|---:|---:|---:|---:|
| device-valid fraction | 91.4% | 92.8% | 86.6% | 87.5% |
| usable after excluding closures | 91.1% | 91.9% | 86.0% | 86.1% |
| median | **2.180 mm** | **2.202 mm** | **2.193 mm** | **2.287 mm** |
| IQR | 0.178 mm | 0.159 mm | 0.217 mm | 0.229 mm |
| p05 – p95 | 1.98 – 2.44 mm | 2.03 – 2.44 mm | 1.97 – 3.31 mm | 2.07 – 3.31 mm |
| coefficient of variation | 0.067 | 0.058 | 0.241 | 0.226 |

Samples taken while an eye is closed are excluded from every derived quantity — a
diameter measured through an eyelid is not a pupil measurement — but they stay in
the table with their flags, so the exclusion is visible.

Left minus right: median −0.027 mm (car), −0.100 mm (motorcycle), p05–p95 spanning
about ±0.3 mm. That is within the tracker's own per-eye error and **no anisocoria
or any other clinical reading is implied**.

The motorcycle's variability is 3.5× the car's (CV 0.24 vs 0.07), and its p95
reaches 3.3 mm against the car's 2.44 mm. That is the pupillary light reflex, not
a behavioural difference — see below.

### Deviation from the local baseline

The local baseline is a centred rolling median over 60 s, computed from real
samples only. A median rather than a mean, because a blink edge or a tracking
dropout would drag a mean and be read back as a pupil change.

Deviations from it are small in both recordings (IQR ≈ 0.04 mm car, ≈ 0.09 mm
motorcycle), which is the expected consequence of a baseline that tracks the
signal at a one-minute scale.

## The light term, and why it has to be removed first

Illuminance differs enormously between the two recordings, because one rider is
behind glass under a roof and the other is in the open:

| | car | motorcycle |
|---|---:|---:|
| median lux | 2 779 | 7 287 |
| p05 – p95 lux | 1 076 – 4 243 | 2 133 – 10 727 |
| observed lux range | 746 – 6 070 | 23 – 18 769 |
| Spearman ρ, diameter vs lux | **−0.55** | **−0.47** |

Comparing raw pupil diameters between these two recordings would substantially be
comparing their glazing. So a light term is removed first: diameter is regressed
on `log10(lux + 1)` by ordinary least squares — log because the reflex is roughly
logarithmic in luminance over the working range, `+1` rather than a clamp because
lux is genuinely near zero in a tunnel and `log(0)` would drop exactly the samples
the correction most needs.

| fitted model | car | motorcycle |
|---|---:|---:|
| slope | −0.0004 m / log₁₀ lux | −0.0012 m / log₁₀ lux |
| Pearson r | −0.591 | −0.915 |
| **R²** | **0.349** | **0.838** |
| paired samples | 10 393 | 26 423 |

The R² values are the point of reporting them. On the motorcycle the light term
accounts for **84%** of the variance in pupil diameter; on the car, 35%. The
motorcycle's much larger raw variability is therefore mostly its light
environment, and any raw-diameter comparison between the two vehicles would have
been reporting that.

The correction is labelled `exploratory` in every artefact, for reasons that do
not go away:

* it is a single covariate fitted by OLS on one session per vehicle;
* it models neither the reflex's latency nor its hysteresis, and both are of the
  order of the timescales here;
* **the ambient-light sensor is head-mounted**, so it follows where the wearer
  looks as much as the scene's illumination. The residual is a *light-adjusted*
  diameter, not a light-free one.

### Residual

| light-adjusted residual | car | motorcycle |
|---|---:|---:|
| median | −0.005 mm | −0.019 mm |
| IQR | 0.108 mm | 0.218 mm |
| p05 – p95 | −0.132 … +0.147 mm | −0.298 … +0.355 mm |

On the shared route the paired difference is **−0.039 mm** (95% CI
[−0.080, −0.016], Cliff's δ = −0.57, p_FDR = 0.015): the motorcycle's pupil is
slightly *smaller* than the car's once light is accounted for. On 30 s time
blocks over the whole recording the same difference is −0.008 mm and does not
survive (p_FDR = 0.635).

That inconsistency between two units of analysis is the honest result. A 0.04 mm
difference is at the edge of what a 2.2 mm measurement from this device supports,
the correction that produced it explains 35% of the variance in one recording and
84% in the other, and the two vehicles' sessions differ in everything else as
well. It is reported and it is not interpreted.

## Event-related response

Full table in `output/article1/final_behavior_statistics/event_response.csv`;
figure `figures/11_event_related_eye_response.png`. Windows are the ones the
road-event analysis already defined (baseline −30…−10 s, anticipation −10…0 s,
immediate 0…+10 s, delayed +10…+40 s) and are built by the same function, so they
are clipped to the recording and trimmed away from neighbouring manoeuvres. Each
is then applied to the eye stream's own real samples.

That trimming dominates what follows. The motorcycle has 62 junctions and 13
roundabouts in 1 004 s, so **81% of baseline windows are clipped** and the median
baseline is 3 s rather than 20 s. An event whose baseline is trimmed away produces
no delta, which is why only 15–23 events carry one on both sides.

Median change from each event's own baseline window to its immediate window:

| event | n car / moto | Δ blink/min car | Δ blink/min moto | Δ closure car | Δ closure moto | Δ pupil residual car | Δ pupil residual moto |
|---|---:|---:|---:|---:|---:|---:|---:|
| roundabout | 6 / 13 | +25.5 | 0.0 | −0.006 | 0.000 | +0.051 mm | +0.114 mm |
| junction | 10 / 62 | −7.7 | 0.0 | −0.039 | −0.008 | −0.024 mm | −0.034 mm |
| curve | 3 / 14 | +39.2 | 0.0 | +0.024 | +0.027 | +0.090 mm | +0.074 mm |
| pedestrian crossing | 7 / 13 | −13.3 | +4.0 | −0.035 | +0.011 | +0.043 mm | +0.089 mm |
| straight | 9 / 25 | +12.0 | −7.5 | 0.000 | −0.023 | −0.041 mm | +0.043 mm |
| solid-line candidate | 5 / 56 | −3.1 | −13.3 | −0.008 | −0.037 | −0.040 mm | −0.040 mm |
| traffic signal | 0 / 1 | — | +21.4 | — | −0.044 | — | +0.544 mm |

**None of these survives FDR**, in either the pooled event comparison or any
per-type one, and the counts are the reason: 3–10 events per type for the car, one
traffic signal in the entire pilot, and a trimmed baseline for many of the rest. A
Δ blink rate over the immediate window — 7 s median after clipping — is quantised
in ~8.6/min steps, which is why the car column moves in large jumps.

The one direction that is weakly consistent across both vehicles is the pupil
residual: up around roundabouts, curves and crossings, down at junctions. That is
as much as it can be.

## Verdict

| item | grade | reasoning |
|---|---|---|
| blink/pupil extraction | **A** | layout read from the file, stream identified by content, decode verified field-by-field against the official binding with zero mismatches on 41 421 samples |
| blink polarity determination | **A** | decided from run lengths, evidence stored, independently corroborated by 96% / 95% agreement with gaze invalidation |
| blink event grouping | **A** | consecutive real samples only, gaps never bridged, five categories with reasons recorded |
| blink rate comparison | **B — usable with exclusions** | large and reproduced across two units of analysis, but the detector is unvalidated and everything else differs between sessions |
| eye-closure fraction | **C — descriptive only** | a measurement, reported as one; no drowsiness reading is supportable and none is offered |
| pupil diameter | **B** | 86–93% valid, physiologically plausible, per-eye difference within tracker error |
| light correction | **C — exploratory** | single covariate, no latency or hysteresis model, head-mounted light sensor; R² 0.35 / 0.84 reported so the reader can weigh it |
| pupil residual comparison | **C — descriptive only** | survives on bins, does not on blocks; 0.04 mm is at the edge of what this device supports |
| any clinical interpretation | **not attempted, and not supportable** | |
